## Statischer Webserver {#compose-webserver}

<span className="kind-tag">Compose</span> Ein nginx, der einen lokalen Ordner read-only ausliefert und nach einem Absturz neu startet.

**So baust du es:**

1. Compose-Datei anlegen; der Startblock *Docker Compose · Projekt* ist schon da.
2. **Compose → Service** unter den Startblock ziehen, Name `web`, Image `nginx:1.27-alpine`.
3. **Service → Port** in den Service legen: Host `8080`, Container `80`.
4. **Service → Volume** in den Service legen: `./html` → `/usr/share/nginx/html`, Häkchen *nur lesen*.
5. **Service → Neustart** `unless-stopped`.

**Blöcke:**

<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk blk-hat" style={{ '--c': '#3f7fd8' }}>Docker Compose · Projekt website Version </span></div>
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#3f7fd8' }}>Service web Image nginx:1.27-alpine</span></div>
<div className="blk-row" style={{ marginLeft: '1.6rem' }}><span className="blk" style={{ '--c': '#7a68d4' }}>Port Host 8080 → Container 80 tcp</span></div>
<div className="blk-row" style={{ marginLeft: '1.6rem' }}><span className="blk" style={{ '--c': '#7a68d4' }}>Volume ./html → /usr/share/nginx/html nur lesen ☑</span></div>
<div className="blk-row" style={{ marginLeft: '1.6rem' }}><span className="blk" style={{ '--c': '#7a68d4' }}>Neustart unless-stopped</span></div>
</div>

**Ergebnis:**

```yaml
name: website
services:
  web:
    image: nginx:1.27-alpine
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html:ro
    restart: unless-stopped
```

:::tip
Ports schreibt BYOBYaml immer in Anführungszeichen (`"8080:80"`). Sonst kann YAML 1.1 Werte wie `22:22` als Zahl im 60er-System lesen.
:::

## App wartet auf gesunde Datenbank {#compose-app-db}

<span className="kind-tag">Compose</span> Die App startet erst, wenn PostgreSQL seinen Healthcheck besteht. Die Daten liegen in einem benannten Volume.

**So baust du es:**

1. Service `db` mit Image `postgres:16-alpine`, drei *Variable*-Blöcke für User, Passwort und Datenbank.
2. *Volume* `pgdata` → `/var/lib/postgresql/data` und *Healthcheck* `pg_isready -U app`.
3. Service `app` mit leerem Image, dafür *Build Ordner* `.`.
4. Im Service `app`: *wartet auf* `db` bis **gesund**.
5. Ganz unten unter dem Startblock: **Compose → Volume** `pgdata`. Benannte Volumes müssen auf oberster Ebene deklariert werden.

**Ergebnis:**

```yaml
name: shop
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: change-me
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test:
        - CMD-SHELL
        - pg_isready -U app
      interval: 10s
      timeout: 5s
      retries: 5
  app:
    build: "."
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://app:change-me@db:5432/app
    depends_on:
      db:
        condition: service_healthy
volumes:
  pgdata:
```

## Image-Tag und Port als Variablen {#compose-variablen}

2. In den Blöcken `${TAG}` und `${PORT}` in die Felder schreiben.

## ConfigMap und Secret in einen Container {#k8s-config-secret}

<span className="kind-tag">Kubernetes</span> Drei Dokumente in einer Datei: ConfigMap, Secret und ein Deployment, das alles als Umgebungsvariablen bekommt.

**So baust du es:**

1. **Ressourcen → ConfigMap** auf die Fläche ziehen, darunter zwei **Config & Daten → Eintrag**-Blöcke.
2. **Ressourcen → Secret** daneben ziehen, darunter ein Eintrag `DB_PASSWORD`.
3. Deployment mit Container. Im Container: *alle Variablen aus ConfigMap* und *Variable … aus Secret … Schlüssel …* für einen einzelnen Wert.

**Blöcke:**

<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#b9613a' }}>Eintrag LOG_LEVEL = info</span></div>
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#b9613a' }}>Eintrag FEATURE_X = true</span></div>
<div className="blk-gap" />
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk blk-hat" style={{ '--c': '#c08a1e' }}>Secret app-secret Typ Opaque</span></div>
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#b9613a' }}>Eintrag DB_PASSWORD = change-me</span></div>
<div className="blk-gap" />
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk blk-hat" style={{ '--c': '#c08a1e' }}>Deployment app Replicas 1</span></div>

<div className="blk-row" style={{ marginLeft: '1.6rem' }}><span className="blk" style={{ '--c': '#2b8fa8' }}>alle Variablen aus ConfigMap app-config Präfix optional ☐</span></div>
<div className="blk-row" style={{ marginLeft: '1.6rem' }}><span className="blk" style={{ '--c': '#2b8fa8' }}>Variable DB_PASSWORD aus Secret app-secret Schlüssel DB_PASSWORD optional ☐</span></div>
</div>

**Ergebnis:**

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  LOG_LEVEL: info
  FEATURE_X: "true"
---
apiVersion: v1
kind: Secret
metadata:
  name: app-secret
type: Opaque
stringData:
  DB_PASSWORD: change-me
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app
spec:
  replicas: 1
  selector:
    matchLabels:
      app: app
  template:
    metadata:
      labels:
        app: app
    spec:
      containers:
        - name: app
          image: registry.example.com/app:1.0
          envFrom:
            - configMapRef:
                name: app-config
          env:
            - name: DB_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: app-secret
                  key: DB_PASSWORD
```

:::tip
`stringData` nimmt Klartext an; Kubernetes speichert ihn base64-kodiert. Das ist **keine Verschlüsselung**.
:::

## Persistenter Speicher {#k8s-pvc}

<span className="kind-tag">Kubernetes</span> Ein PVC wird als Volume im Pod definiert und im Container eingehängt. Der Name `data` verbindet beides.

**So baust du es:**

1. **Ressourcen → Speicher (PVC)** `app-data`, `5Gi`, `ReadWriteOnce`.
2. Im Deployment: **Pod → Volume aus PVC** mit Name `data` und Claim `app-data`.
3. Im Container: **Container → Volume einhängen** mit Name `data` und Pfad `/var/lib/app`.

**Blöcke:**

<div className="blk-tree">
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk blk-hat" style={{ '--c': '#c08a1e' }}>Speicher (PVC) app-data Größe 5Gi Zugriff ReadWriteOnce</span></div>
<div className="blk-gap" />
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk blk-hat" style={{ '--c': '#c08a1e' }}>Deployment app Replicas 1</span></div>
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#c9702a' }}>Volume data aus PVC app-data</span></div>
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#c9702a' }}>Container app Image registry.example.com/app:1.0</span></div>
<div className="blk-row" style={{ marginLeft: '1.6rem' }}><span className="blk" style={{ '--c': '#2b8fa8' }}>Volume data einhängen in /var/lib/app nur lesen ☐ Unterpfad </span></div>
</div>

**Ergebnis:**

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: app-data
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 5Gi
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app
spec:
  replicas: 1
  selector:
    matchLabels:
      app: app
  template:
    metadata:
      labels:
        app: app
    spec:
      containers:
        - name: app
          image: registry.example.com/app:1.0
          volumeMounts:
            - name: data
              mountPath: /var/lib/app
      volumes:
        - name: data
          persistentVolumeClaim:
            claimName: app-data
```

:::tip
Bei `ReadWriteOnce` kann nur ein Node das Volume einhängen. Für mehrere Replicas auf verschiedenen Nodes brauchst du `ReadWriteMany` oder ein StatefulSet mit *pro Pod Speicher*.
:::

## Ingress mit TLS und zwei Pfaden {#k8s-ingress}

<span className="kind-tag">Kubernetes</span> Ein Hostname, zwei Backends: `/` geht ans Frontend, `/api` an die API. Das Zertifikat stellt cert-manager aus.

**So baust du es:**

1. **Ressourcen → Ingress** mit Klasse `nginx`.
2. **Netzwerk → cert-manager Issuer** `letsencrypt` und **TLS für** Host plus Secret-Name.
3. Zwei **Regel**-Blöcke mit demselben Host. BYOBYaml fasst sie unter einem `host` zusammen.

**Blöcke:**

<div className="blk-tree">
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk blk-hat" style={{ '--c': '#c08a1e' }}>Ingress shop Klasse nginx</span></div>
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#3a9558' }}>cert-manager Issuer letsencrypt</span></div>
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#3a9558' }}>TLS für shop.example.com mit Secret shop-tls</span></div>
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#3a9558' }}>Regel Host shop.example.com Pfad / → Service frontend Port 80 Abgleich undefined</span></div>
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#3a9558' }}>Regel Host shop.example.com Pfad /api → Service api Port http Abgleich undefined</span></div>
</div>

**Ergebnis:**

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: shop
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - shop.example.com
      secretName: shop-tls
  rules:
    - host: shop.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: frontend
                port:
                  number: 80
          - path: /api
            pathType: Prefix
            backend:
              service:
                name: api
                port:
                  name: http
```

:::tip
Steht im Port-Feld eine Zahl, wird daraus `port.number`. Steht dort ein Name wie `http`, wird daraus `port.name`.
:::

## Nächtlicher CronJob {#k8s-cronjob}

<span className="kind-tag">Kubernetes</span> Ein Backup um 02:00 Uhr. Läuft noch ein alter Job, startet kein neuer; dafür sorgt ein Extras-Feld.

**So baust du es:**

1. **Ressourcen → CronJob** mit Zeitplan `0 2 * * *`.
2. **Extras → Feld** `spec.concurrencyPolicy` = `Forbid`. Diese Option hat keinen eigenen Block.
3. Container mit *Command*. Anführungszeichen halten Argumente zusammen.

**Blöcke:**

<div className="blk-tree">
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk blk-hat" style={{ '--c': '#c08a1e' }}>CronJob backup Zeitplan 0 2 * * *</span></div>
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#5f6b82' }}>Feld spec.concurrencyPolicy = Forbid</span></div>
<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#c9702a' }}>Container backup Image alpine:3.20</span></div>
<div className="blk-row" style={{ marginLeft: '1.6rem' }}><span className="blk" style={{ '--c': '#2b8fa8' }}>Command /bin/sh -c "tar czf /backup/data.tgz /data"</span></div>
</div>

**Ergebnis:**

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: backup
spec:
  schedule: 0 2 * * *
  jobTemplate:
    spec:
      template:
        metadata:
          labels:
            app: backup
        spec:
          containers:
            - name: backup
              image: alpine:3.20
              command:
                - /bin/sh
                - -c
                - tar czf /backup/data.tgz /data
          restartPolicy: OnFailure
  concurrencyPolicy: Forbid
```

## Extras: Felder ohne eigenen Block {#k8s-extras}

<div className="blk-row" style={{ marginLeft: '0rem' }}><span className="blk" style={{ '--c': '#c9702a' }}>Container worker Image registry.example.com/worker:2.0</span></div>
<div className="blk-row" style={{ marginLeft: '1.6rem' }}><span className="blk" style={{ '--c': '#5f6b82' }}>Feld lifecycle.preStop.exec.command = [sh, -c, sleep 5]</span></div>
</div>

**Ergebnis:**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: worker
  annotations:
    app.openshift.io/connects-to: db
spec:
  replicas: 2
  selector:
    matchLabels:
      app: worker
  template:
    metadata:
      labels:
        app: worker
    spec:

                command:
                  - sh
                  - -c
                  - sleep 5
      tolerations:
        - key: dedicated
          operator: Equal
          value: batch
          effect: NoSchedule
```

**Ergebnis:**

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: web
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
    - type: Resource
      resource:
        name: memory
        target:
          type: Utilization
          averageUtilization: 80
  behavior:
    scaleDown:
      stabilizationWindowSeconds: 300
```

:::tip
Auslastung bezieht sich auf die **requests** der Container. Ohne `resources.requests` kann der HPA nicht rechnen.
:::
